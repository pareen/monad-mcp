🛠 Developer guide — the write-enabled dev version

Run monad-mcp yourself

The hosted endpoint is read-only on purpose. This is the dogfood path: get the server running on your laptop with a Privy signer, point Claude Desktop at it, and have a real conversation that moves real testnet MON — transfers, swaps, staking, and hands-off session keys.

Start with prereqs ↓ Just want read tools? Use the hosted URL
Read-only is easier. If you only need balances, prices, portfolios, and contract reads, you don't need any of this — point your client at the hosted URL https://monad-mcp.fly.dev/mcp on the connect page. This guide is specifically for unlocking the write tools, which require a signer.

1 · Prerequisites

  • Node ≥ 20.10
  • Claude Desktop installed and signed in
  • A Privy app created at dashboard.privy.io (App ID + App Secret)
  • A funded testnet wallet (you'll provision one below, then fund it from the Monad faucet)

Everything write-related hinges on Privy: the user's embedded wallet signs, never the agent and never the server. The server only ever builds unsigned transactions.

2 · Clone & build

git clone https://github.com/pareen/monad-mcp.git
cd monad-mcp
npm install
npm run build

This emits dist/index.js (the stdio entrypoint Claude Desktop spawns) and dist/server-http.js (the approval-flow webserver).

3 · Privy & signing setup

Copy .env.example to .env and add your Privy PRIVY_APP_ID and PRIVY_APP_SECRET. Then run the one-time bootstrap and provision a test user:

Bootstrap the authorization key
npm run bootstrap:auth-key

This writes PRIVY_AUTHORIZATION_PRIVATE_KEY and PRIVY_KEY_QUORUM_ID into your .env — the credentials that let the server request signatures from Privy as an additional signer.

Provision & fund a test user
npm run e2e:create-user

Fund the printed address from the Monad testnet faucet so you have MON to move.

Run bootstrap first. Wallets minted before the bootstrap step (without additional_signers) can't be signed for from the server — they're stranded. Always run npm run bootstrap:auth-key before creating users.

4 · Wire into Claude Desktop

Open the Claude Desktop config:

# macOS
open ~/Library/Application\ Support/Claude/claude_desktop_config.json
# Linux:   ~/.config/Claude/claude_desktop_config.json
# Windows: %APPDATA%/Claude/claude_desktop_config.json

Add the monad entry (keep any existing servers). The --env-file flag loads your PRIVY_* / MONAD_* / NOTIFICATION_* vars into the spawned process — without it, the server boots read-only and writes fail.

{
  "mcpServers": {
    "monad": {
      "command": "node",
      "args": [
        "--env-file=/absolute/path/to/monad-mcp/.env",
        "/absolute/path/to/monad-mcp/dist/index.js"
      ]
    }
  }
}

Quit Claude Desktop completely (⌘Q on macOS — closing the window isn't enough) and reopen it. Then ask “What MCP servers are connected?” — you should see monad with its read + write tools. If it's missing, check the log at ~/Library/Logs/Claude/mcp-server-monad.log (usually a missing env var or a port conflict).

5 · Run the approval server

Write tools return an approval URL like http://localhost:8787/approve/<id>. That page is served by the HTTP server — run it in a second terminal:

npm run start:http
# → monad-mcp http server listening on http://localhost:8787

To approve from anywhere (not just your laptop's localhost), expose it and set the public base URL before booting:

ngrok http 8787
# then in .env:
PUBLIC_BASE_URL=https://<your-ngrok-domain>

6 · First prompts & session keys

Smoke tests first (read-only, no funds moved):

What's the balance of 0x7E274bCA90eEfa81761080e074AFb1D354a0c552 on Monad testnet?
List the canonical Monad tokens.
Get a portfolio for 0x7E274bCA90eEfa81761080e074AFb1D354a0c552.

Then a real transfer:

Send 0.001 MON from my wallet to 0x000000000000000000000000000000000000dEaD on Monad testnet.

Claude calls whoami to find your wallet, then transfer, and hands you an approval URL. Click it, review the simulated asset diff, approve. Privy signs; Claude polls poll_request and reports the tx hash.

Now grant a session key for hands-off agent loops:

Grant the agent up to 0.05 MON for the next 24 hours, no recipient restriction.
After you approve the grant once, subsequent transfers under the cap auto-execute and return tx hashes immediately — no second click. Each grant is also mirrored as a Privy wallet policy, so Privy itself refuses anything outside the budget, expiry, and allowlists you set.

7 · Connect from source (Claude Code)

Prefer Claude Code, or want to run your own modified build? Point it at the built entrypoint with an absolute path:

claude mcp add monad -- node /absolute/path/to/monad-mcp/dist/index.js

Pass Privy credentials as env vars to unlock writes here too:

claude mcp add monad \
  --env PRIVY_APP_ID=clxxxx \
  --env PRIVY_APP_SECRET=xxxx \
  --env MONAD_DEFAULT_NETWORK=testnet \
  -- npx -y monad-mcp

Until those are set, the server runs happily read-only and write tools return a clear “sign in via Privy” message rather than failing silently.

8 · Deploy your own endpoint

To run a stable, always-on, write-enabled endpoint, deploy the HTTP transport (dist/server-http.js) with your Privy secrets. The repo ships a Dockerfile and fly.toml:

fly auth login
fly launch --copy-config --now
# once it's up, add the Privy secrets to switch /mcp to write mode:
fly secrets set \
  PRIVY_APP_ID=clxxxx \
  PRIVY_APP_SECRET=xxxx \
  PRIVY_AUTHORIZATION_PRIVATE_KEY=... \
  PRIVY_KEY_QUORUM_ID=... \
  PUBLIC_BASE_URL=https://<app-name>.fly.dev

With no Privy secrets the endpoint is an open, read-only gateway (safe to make public). Once PRIVY_APP_ID/PRIVY_APP_SECRET are present, /mcp switches to requiring an OAuth 2.1 bearer token and the approval flow goes live. The Dockerfile is plain, so Railway, Render, or Cloud Run work too. Full runbook — env vars, health checks, npm publish — is in docs/DEPLOY.md.

9 · Known issues

  • stdio clients don't run the OAuth flow. Claude Desktop on stdio assumes the local user is the one running the server — fine in dev. In production you'd run the HTTP transport with bearer auth.
  • Approval URLs need the HTTP server up. They only resolve while npm run start:http is running. For hands-off, run it as a launchd service (macOS) or systemd unit (Linux).
  • Stranded wallets. Wallets minted before bootstrap:auth-key have no additional_signers and can't be signed for. Always bootstrap first.

10 · Iterating

Stdio MCP servers don't hot-reload: edit code → npm run build → restart Claude Desktop (⌘Q + reopen). For faster iteration without Claude Desktop, drive the stdio server directly with the MCP inspector:

npx @modelcontextprotocol/inspector dist/index.js
